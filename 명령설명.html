가상환경 — 참가자가 직접 활성화할 필요 없음

edu1-1 같은 이름은 ~/.local/bin 의 심링크이고, 연결된 스크립트가 실행되면서 파이썬 환경을 자동으로 설정합니다. common.sh → config.sh → _env.sh 를 차례로 읽고 edu_activate 가 환경을 찾아 PATH 를 설정합니다. 명령 앞에 activate 를 입력하지 마세요.

활성화된 환경은 그 명령 안에서만 유효합니다. 스크립트는 별도 프로세스이므로, 명령이 끝나면 터미널은 실행 전 상태 그대로입니다. 프롬프트에 (lerobot) 같은 표시가 나타나지 않는 것이 정상이며, 고장이 아닙니다.

따라서 lerobot-train · python 을 직접 입력할 때만 환경을 직접 활성화하세요 :

source ~/so101_lerobot_env/bin/activate

이 PC 의 실제 환경은 conda 가 아니라 venv ~/so101_lerobot_env 입니다. conda 가 설치되어 있지만 base 하나뿐이고 config.sh 가 가리키는 lerobot 환경은 없습니다. 그래서 첫 줄에 아래 한 줄이 표시되는데, 경고가 아니라 어느 환경을 선택했는지 알리는 줄입니다.

$ edu1-1 ⓘ venv 사용 : /home/ketri/so101_lerobot_env ══════════════════════════════════════════════════════ 1-1 · 텔레옵 (카메라 없음)

찾는 순서는 일곱 단계입니다. 찾지 못하면 그냥 넘어가지 않고, 조치 방법을 안내한 뒤 멈춥니다.

순서보는 곳
⓪EDU_PY 로 직접 지정한 파이썬
①이미 활성화된 환경 — CONDA_ENV 와 이름이 같거나, venv 가 활성화되어 있으면 그대로 사용
②PATH 에 lerobot-train 이 있는지 (venv · pipx · 시스템 설치)
③config.sh 의 CONDA_SH → 흔한 conda 설치 위치 여섯 곳
④conda 환경 목록에서 lerobot-train 이 설치된 환경을 이름과 무관하게 탐색
⑤흔한 venv 위치 — 이 PC 는 여기서 찾음 (~/so101_lerobot_env)
⑥conda 가 없어도 현재 파이썬에서 pandas·pyarrow 를 불러올 수 있으면 그대로 사용

환경을 옮겼거나 이름이 다르면 아래 셋 중 하나로 지정하세요.

값어디에무엇
EDU_PY명령 앞에파이썬 직접 지정 — 가장 확실한 방법. EDU_PY=/경로/bin/python3 edu1-1
CONDA_ENVconfig.shconda 환경 이름. 현재 값은 lerobot 이지만 이 PC 에는 해당 환경이 없어 ⑤ 로 넘어감
CONDA_SHconfig.shconda.sh 경로. 현재 값은 ~/miniforge3/etc/profile.d/conda.sh

pandas · pyarrow · rerun 이 빠져 있으면 그 자리에서 미리보기와 [y/N] 확인을 거쳐 설치합니다. lerobot 최소 설치 시 빠지는 패키지이므로 설치 오류가 아닙니다 — pandas·pyarrow 는 dataset, rerun 은 viz extra 에 속합니다. 인터넷이 없으면 pip 이 오래 멈추지 않도록 먼저 연결을 확인하고 짧게 중단한 뒤 설치할 수 없다고 안내합니다.

환경이 제대로 설정됐는지는 edu-set 의 ── 파이썬 ── 두 줄로 확인하세요. 여기에 ✘ 가 표시되면 이후의 모든 명령이 실행되지 않습니다.

에피소드 100개를 세션당 10개씩 나누어 녹화합니다. 세션이 끝날 때마다 멈춰서 방금 녹화한 에피소드를 확인하고, 이상 에피소드를 삭제한 뒤, 다음 세션으로 넘어갑니다. 기존 데이터셋이 있으면 자동으로 이어서 녹화합니다 — 삭제 여부를 묻지 않습니다.

세션으로 나누는 이유 — 100개를 연달아 녹화한 뒤 문제를 발견하면 되돌릴 방법이 없습니다. 10개마다 나누면 최악의 경우에도 10개만 다시 녹화하면 됩니다.

병합이 끝나면 이름 교체 여부를 묻습니다. 교체하면 병합본이 원래 녹화본 이름을 쓰고, 원래 녹화본은 _old 로 백업됩니다. 그러면 다음 단계에서 긴 경로를 입력하지 않아도 병합본으로 학습할 수 있습니다.

so101_edu → so101_edu_old

so101_edu_merged → so101_edu

학습 : RUN=2 edu3-1 · 롤아웃 : RUN=2 edu4-1

교체 안 함 [n]

병합본은 so101_edu_merged 에 그대로 남습니다.

학습할 때 직접 지정하세요 :

EDU_REPO_ID=data/so101_edu_merged RUN=2 edu3-1

병합 직후 index 교정이 한 번 실행됩니다. lerobot 0.6.x 의 버그로 병합 결과를 다시 병합에 쓰면 실패하는데, 이를 미리 교정합니다. 학습에는 영향이 없습니다.

⚠ 1차 학습(act_edu_r1)과 결과를 구분하려면 RUN=2 로 학습하고, 롤아웃도 RUN=2 edu4-1 로 실행하세요. RUN=2 를 빼고 edu4-1 만 실행하면 1차 모델이 실행됩니다.

edu3-1 — 학습

시작하면 어떤 데이터로 얼마나 학습할지를 먼저 보여 줍니다. 에폭은 스텝 × 배치 ÷ 프레임 으로 계산해 표시합니다.

$ edu3-1 ══════════════════════════════════════════════════════ 3-1 · 학습 데이터 : data/so101_edu (에피소드 100개 · 32225프레임) 정책 : act 스텝 : 30000 · 배치 8 → 약 7.5 에폭 예상 : 약 44분 출력 : .../outputs/train/act_edu_r1 (회차 1) 학습 중에는 GPU 를 쓰는 다른 작업을 실행하지 마세요. ══════════════════════════════════════════════════════ 로그 : .../outputs/train/_logs/act_edu_r1-20260908-101500.log

참고 사항

  • 출력 폴더가 이미 있으면 lerobot 은 덮어쓰지 않고 오류를 냅니다. 1차 결과를 보존한 채 다시 학습하려면 회차를 올리세요 : RUN=2 edu3-1 (롤아웃도 같은 회차로 실행 : RUN=2 edu4-1)
  • 데이터를 추가 녹화한 뒤 다시 학습할 때는 --resume 을 쓰지 마세요. 처음부터 새로 학습하고 출력 이름만 바꾸세요
  • 5,000스텝마다 중간 체크포인트가 저장됩니다. 중간 체크포인트로 롤아웃하려면 config.sh 의 CKPT 를 해당 번호로 바꾸세요
  • 학습 중에는 GPU 를 쓰는 다른 작업을 실행하지 마세요 — 메모리 부족으로 학습이 중단됩니다

edu3-2 — 손실 곡선

학습이 제대로 진행되는지를 눈으로 확인합니다. GPU 를 전혀 쓰지 않으므로 학습 중에 실행해도 됩니다. Chrome 탭이 열리고 20초마다 갱신됩니다. W&B 없이 stdout 로그만 읽어 그래프를 그립니다.

실행 방법표시 내용
edu3-2내 최신 학습 로그. 20초마다 갱신
edu3-2 --once한 번만 표시 (정지 화면)
edu3-2 --golden골든 모델을 만든 학습의 기준 곡선. 내 곡선과 나란히 놓고 비교
edu3-2 <로그파일>특정 로그. 이어학습이면 여러 개를 순서대로 지정

읽는 법 — 곡선이 내려가면 학습이 진행 중입니다. 평탄해지면 더 학습해도 크게 나아지지 않습니다. 곡선이 내려가지 않으면 대개 데이터 문제입니다 — 스텝을 늘리기 전에 edu2-2 로 녹화본을 다시 확인하세요.

--follow 로 실행하면 로그가 5회 연속 늘지 않을 때 (학습 종료로 판단) 자동으로 종료됩니다. --golden 은 이미 끝난 학습이라 갱신할 내용이 없으므로 자동으로 정지 화면이 됩니다.

바

4단계 · 롤아웃 — edu4-1 · edu4-2

리더암을 쓰지 않습니다. 로봇이 스스로 움직입니다. 카메라 영상과 현재 관절 각도를 모델에 입력하고, 출력된 동작을 그대로 팔에 전달합니다.

처음 몇 초는 손을 팔 근처에 두고 언제든 중단할 수 있도록 준비하세요.

리더암 없음 — 4단계에서 사람이 하는 일은 원통을 놓아 주고, 지켜보다가 필요하면 중단하는 것뿐입니다.

edu4-1 — 내 모델 롤아웃

config.sh 의 CKPT 가 가리키는 체크포인트로 로봇팔을 구동합니다. 기본값은 방금 학습한 회차의 checkpoints/last 입니다. 체크포인트가 없으면 먼저 학습하라고 안내하고 멈춥니다.

체크포인트 경로는 RUN 회차를 따라갑니다. RUN=2 edu3-1 로 학습했다면 RUN=2 edu4-1 로 실행하세요 — RUN 없이 실행하면 1차 모델이 실행됩니다.

롤아웃 중 할 일

  • 원통을 여러 위치에 놓아 보세요 — 가운데만 되는지, 가장자리도 되는지
  • 실패하는 위치를 기록하세요. 그 위치가 다음에 추가 녹화할 위치입니다
  • 끝나면 rollout-기록.md 에 한 줄 기록하세요 — 모델 / 추론 / 값 → 관찰

edu4-2 — 골든 모델 롤아웃

미리 검증해 둔 모델로 로봇팔을 구동합니다. 당일 학습 결과가 좋지 않을 때의 대비책이자, 잘 된 결과의 본보기입니다. 학생 모델과 번갈아 실행해 보면 차이가 바로 보입니다.

항목현재 모델
경로models/act_golden (폴더에 함께 포함 · 198 MB)
정체act_edu3_100 의 checkpoints/060000
학습 데이터골든 데이터 so101_edu3 — 에피소드 100개 · 40,636프레임
학습량ACT 60,000스텝 · 배치 8 — 약 11.8 에폭
추론sync · rename_map 없음
같은 학습의 곡선edu3-2 --golden

다른 모델로 바꾸려면 config.sh 의 세 줄만 수정하세요.

  • ACT 계열 → STABLE_INFERENCE_TYPE=sync · STABLE_RENAME_MAP 은 비워 둠
  • SmolVLA 계열 → STABLE_INFERENCE_TYPE=rtc · STABLE_RENAME_MAP 을 채움. rename_map 이 없으면 카메라 이름 불일치로 실행이 실패합니다 — 그래서 4-2 가 미리 경고하고 계속할지 묻습니다

비워 두면 4-2 는 실행하지 않고 사용 가능한 학습 결과 목록을 보여 줍니다.

추론 값을 그 자리에서 바꿔 볼 수도 있습니다 — edu4-2 --policy.n_action_steps=1 --policy.temporal_ensemble_coeff=0.01 처럼 뒤에 붙이면 그대로 lerobot-rollout 으로 전달됩니다.
